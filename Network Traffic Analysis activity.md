# Cybersecurity Incident Report:  Network Traffic Analysis

| Part 1: Provide a summary of the problem found in the DNS and ICMP  traffic log.  |  |
| :---- | ----- |
| At 1345 yummyrecipesforme.com contacted Generic IT Services reporting that their website was down. When attempting to access the website, users had reported an error message reading “udp port 53 unreachable”. Three attempts were made, at 1324, 1326 and 1328 between IP 192.51.100.15.52444 and the server IP 203.0.113.2.53 to access the website and each received the same response. Each was unsuccessful, as evidenced by the retention of the request number 35084\. The length of responses varied with lengths of 254, 320 and 150 being returned on the first, second and third attempts, respectively. Network protocol analysis was undertaken using tcpdump. The error took place as part of the DNS protocol in which a UDP data packet is sent to the DNS server to obtain the IP address of the website. An Internet Control Message Protocol (ICMP) was instead received and not the IP address, indicating that no response was received from port 53, the port responsible for handling DNS requests. Given the response is consistent with a DNS protocol error, it is likely that the DNS server is functioning as it could send a response, but not responding. |  |
|  |  |

| Part 2: Explain your analysis of the data and provide at least one cause of the incident. |
| :---- |
| **Analysis** The same error returned to the users reporting that they could not access the website is that which I received when trying to access the website as part of my investigation. This indicates it is not a problem confined to a specific user device or user. This error message of UDP Port 53 being unreachable was consistent across all three requests made. Given that the ICMP error returned is linked to the expected operation at this stage, a DNS request, and indicated that my browser received no response from port 53, the port typically used for DNS requests by the DNS server, there is a plausible error with the DNS server which will require investigation. The fact that a response was received indicates that the DNS host is running, and that the server is at a minimum impaired on port 53\. Possible causes are a Denial of Service attack rendering port 53 unusable, or a configuration issue such as the website provider’s firewall blocking traffic to port 53\. Further investigation will be required in order to confirm the cause. |
