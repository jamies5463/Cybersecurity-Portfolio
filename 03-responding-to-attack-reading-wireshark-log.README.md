# Cybersecurity Incident Report

| Section 1: Identify the type of attack that may have caused this  network interruption |  |
| :---- | ----- |
| At 1403 on 12/08/2026 reports were received that the organisation’s website, www\.amazingtrips.co.uk, was down. My own attempt to access the website resulted in the website failing to load and the notification “This site can’t be reached” being returned. Using a Network Protocol Analyser (NPA), Wireshark pcap analysis showed an unusually high number of SYN requests being sent by an unknown IP address, corresponding with a SYN attack. This is detailed below. At 1347 the IP address 203.0.113.0 made a SYN request to website server. Over a 17 second period these requests increased in frequency and after a period of 21 seconds, the IP made 89 requests over a 30 second period.  In response the following actions were undertaken: The server was taken offline to allow it to recover. Before reconnecting the server, the firewall was configured to block the IP address which had been sending the requests. This step is likely to only provide temporary protection from the attacker, who may change IP address using IP spoofing and attempt further attacks. The Network Operations Lead was made aware of the attack and advice was sought on next steps. |  |

| Section 2: Explain how the attack is causing the website to malfunction |
| :---- |
| When website visitors try to establish a connection with the web server, a three-way handshake occurs using the TCP protocol.  1\. **SYN**: SYN is short for synchronise, and is the first stage in establishing a Transmission Control Protocol (TCP) connection. The TCP protocol allows for two devices, in this case a user’s device such as phone or laptop, and the company’s website server, to establish a secure connection and ensure proper delivery of data. This stage is initiated by the user attempting to visit the website.  2\. **SYN-ACK**: SYN-ACK is the second stage in the three-way handshake. It is a response from the server to the user acknowledging and agreeing to the request to synchronise.  3\. **ACK**: Is the final stage of the three-way handshake, sent from the user to the server, acknowledging the server’s response and confirming that the user device and server can begin data transmission. The large number of SYN requests and the unknown IP address are typical of a SYN flood attack, whereby an attacker uses a spoofed IP address to stage the attack. A SYN flood relies on an attacker sending a large number of SYN requests to a server as part of a Denial of Service (DoS) attack. The server becomes unable to respond to the number of requests and becomes overwhelmed, ceasing to function. As the initiating SYN request requires a response from the server, the server is left with a large number of “open” three-way handshakes to which it needs to respond. DoS attacks stand in contrast to interception attacks and therefore possess different indicators. Given that a DoS attack is typically reliant on exploiting legitimate protocols such as TCP/IP to overwhelm servers, evidence is often found in network activity through identifying a large number of requests, or in some instances singular large requests such as the “ping of death”. Interception attacks, so called owing to their reliance in intercepting data in transit and preventing it from arriving, delaying it, or stealing its contents, have a different set of indicators when analysing network activity. A further type of attack is a backdoor attack: if a DoS attack relies on knocking out a service through exploiting legitimate protocols, and interception attacks rely on stealing data in transit, backdoor attacks exploit weaknesses such as a port left open in software to gain access to a service/network/device to which the attacker should not have access. These categories of attack should not be understood as discrete as they can be combined, for example an attacker exploiting an open port to gain access to a network and using this to intercept data in transit within the network. All types of attack ultimately pose harm to organisations. At the milder end, a user may simply stop using a service if whenever they try to access it, it does not work owing to a DoS attack. At the extreme end, sensitive personally identifiable interception (SPII) such as bank account information can be stolen, resulting in real world harms to individuals, reputational damage to organisations, fines from regulators, and lost revenue through responding to attacks and individuals choosing to avoid that organisation for fear of harm.  |
